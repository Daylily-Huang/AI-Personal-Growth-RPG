## Non-negotiable invariants

- Time is not XP.
- XP is not Mastery.
- High Mastery requires Evidence.
- LLM produces proposals; application code commits permanent growth state.
- Final XP is computed by deterministic Growth Engine code.
- Every XP mutation must be traceable through the ledger.
- Repetition must reduce XP unless a real breakthrough occurs.
- Failure may produce Learning XP.
- Temporary state must not be confused with permanent capability.
- User-private tables require RLS.
- Never expose OpenAI or Supabase service-role secrets to the browser.
- Do not add gambling, loot-box, forced-streak, shame, or punitive engagement mechanics.

## Scope discipline

Before implementation, state:

- IN SCOPE
- OUT OF SCOPE
- files to modify
- migrations
- tests
- acceptance criteria

Do not expand scope without explicit reason.

## Mandatory harness rules

If modifying:

`src/lib/growth-engine/**`

run:

```bash
pnpm harness:deterministic
```

If modifying:

`src/lib/ai/prompts/**`
`src/lib/ai/schemas/**`
AI model configuration

run applicable:

```bash
pnpm harness:llm:golden
```

If modifying:

- confirmation flow
- auth
- RLS
- migrations
- XP transactions

run:

```bash
pnpm test
pnpm harness:deterministic
pnpm harness:e2e
```

Never update a baseline merely to make a failing test pass.

## Rule changes

Do not autonomously change:

- Growth Constitution
- XP philosophy
- Mastery definitions
- Evidence ladder
- permanent-vs-temporary distinction
- AI database authority
- anti-farming philosophy

If a change is necessary, present alternatives and wait for explicit user choice.

## Coding principles

Prefer:

- small
- testable
- traceable
- reversible
- typed
- server-authoritative

Avoid:

- premature microservices
- duplicated business logic
- arbitrary SQL generated by LLM
- broad `any`
- silent catch blocks
- hidden state mutations
