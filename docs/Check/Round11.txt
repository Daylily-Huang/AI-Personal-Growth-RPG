# 九、Stage2 的 RPC 必须把数据库当“裁判”，不是普通 CRUD 包装

我建议最终的流程是：

```text
Browser
↓
POST confirm

Next.js server
↓
User-scoped Supabase client
↓
load Activity + Assessment

SettlementService
↓
calculateXp()
checkMasteryProposal()
↓
产生 command

settle_activity(command)
↓
PostgreSQL transaction
```

然后 RPC 内部：

```text
1. v_user_id := auth.uid()

2. assessment 必须：
   owner = v_user_id
   status = pending

3. activity 必须：
   owner = v_user_id
   未结算

4. resolve/create Skill

5. 事务内重新计算 authoritative repetitionCount

6. 如果和 command 不同：
   返回 repetition_conflict

7. UNIQUE / idempotency guard

8. insert XP ledger

9. player.total_xp += xp

10. skill.xp += xp

11. mastery：
    只能单调 increase
    或 pending verification

12. siblings → superseded

13. assessment → confirmed

14. activity → confirmed

15. return authoritative persisted result
```

这就是 Stage2 的核心。

# 十、`SECURITY DEFINER` 是下一轮最危险的位置

后面如果这里写错，前面的 RLS 可以全部被绕过去。

Stage2 RPC 必须遵守几条硬规则：

### 1. 不允许 client 传可信 `user_id`

不要：

```sql
settle_activity(
  p_user_id uuid,
  ...
)
```

然后：

```sql
where user_id = p_user_id
```

必须：

```sql
v_user_id := auth.uid();
```

---

### 2. RPC 自己验证 Assessment / Activity ownership

例如：

```sql
select ...
from ai_assessments
where id = p_assessment_id
and user_id = auth.uid()
for update;
```

不是信任前端。

---

### 3. 固定 `search_path`

不要裸：

```sql
security definer
```

至少：

```sql
security definer
set search_path = public, pg_temp
```

更严格的话函数里 schema 全部显式：

```sql
public.skills
public.activities
...
```

---

### 4. 控制 EXECUTE 权限

不要默认整个世界都能调用。

明确：

```sql
revoke execute ...
from public;

grant execute ...
to authenticated;
```

这类细节下一轮我会专门查。

# 十二、Composite Tenant FK 可以 Stage2 顺手做，但我不要求一次覆盖所有表

不要又进入“大修 17 张表”。

核心 Growth Loop 优先：

```text
ai_assessment
↔ activity

xp_transaction
↔ activity
↔ assessment
↔ skill

mastery_verification
↔ skill
```

优先建立：

```text
(user_id, id)
```

composite identity。

例如：

```sql
unique (user_id, id)
```

以及：

```sql
foreign key (
  user_id,
  activity_id
)
references activities (
  user_id,
  id
)
```

这样数据库能保证：

```text
User A 的 transaction
永远不能指向 User B 的 activity
```

后面 knowledge/artifact 可以下一 milestone 再收。
