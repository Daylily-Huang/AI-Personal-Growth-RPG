# 5. Confirm 并发问题：这次文档说法准确多了

它补了：

```ts
await Promise.all([
  confirmAssessment(id),
  confirmAssessment(id),
]);
```

并要求：

```text
1 success
1 already_confirmed
transactions.length = 1
```



但这里有一个技术细节需要说明。

`confirmAssessment()` 本身是**同步函数**。

因此：

```ts
Promise.all([
  confirmAssessment(),
  confirmAssessment()
])
```

并不会制造真正的异步 race。

实际上执行更接近：

```text
第一个完整执行结束
↓
第二个执行
```

所以这个测试严格来说仍不是：

> 真正的 concurrent storage race test。

但是这次开发 AI 已经在文档里承认了这个边界：

```text
单 Node 进程：
同步读改写，实际串行

跨进程 / 多实例：
当前不保证
```

并明确把最终保证放在 PostgreSQL `UNIQUE` 上。

所以我现在接受这个设计。

### 判定

**PASS for Demo**

而不是：

**Production concurrency PASS**

二者不能混为一谈。

# 8. 我发现一个新的小问题：AI Proposal 里的 repetition_risk 现在会失真


这个技术逻辑可以理解。

于是可能出现 UX 矛盾：

```text

repetition ×0.4
```
