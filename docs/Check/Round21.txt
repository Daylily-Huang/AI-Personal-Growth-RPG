# P2-2：0029 只收紧了 Tables / Sequences，没有收紧 Future Functions

这是一个容易遗漏但值得现在补掉的 DB hardening。

0029 目前：

```sql
REVOKE ALL ON TABLES
REVOKE ALL ON SEQUENCES
```



但是 PostgreSQL 对**新建 function / procedure** 默认会给：

```text
PUBLIC EXECUTE
```

官方文档明确如此。

而你的系统后面一定还会继续加：

```text
SECURITY DEFINER RPC
```

例如：

```text
resolve_mastery_verification()
apply_correction()
merge_skills()
...
```

如果未来某次 migration 忘记：

```sql
REVOKE ALL ... FROM PUBLIC;
```

就可能临时或永久暴露 trusted RPC。

所以真正的 fail-closed default authority 最好再补：

```sql
ALTER DEFAULT PRIVILEGES
REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC;
```

注意 PostgreSQL 官方文档特别说明：这个 revoke 不能只写成 schema-local 版本，要针对创建者角色的 global default privileges 做。

不是当前 blocker，但在下一个 SECURITY DEFINER RPC 出现前应该解决。

# P2-4：redirect helper 复制“全部 NextResponse headers”过于宽

现在：

```ts
sourceResponse.headers.forEach((value, key) => {
  redirectResponse.headers.set(key, value);
});
```



但 `sourceResponse` 是：

```ts
NextResponse.next({
  request: {
    headers: request.headers
  }
})
```

NextResponse 在这种模式下内部会携带：

```text
x-middleware-override-headers
x-middleware-request-*
x-middleware-next
```

这类 Next 内部控制 headers。Next 本身确实用这些 header 实现 request header override。

当前实现大概率仍能工作，因为 Next server 会处理/移除这些内部字段，但设计不够干净。

更稳的模式是分别保存：

```text
pendingCookies
pendingSupabaseHeaders
```

redirect 时只复制：

```text
Supabase 提供的 cache headers
+
refresh cookies
```

而不是复制整个 `NextResponse.next().headers`。

当前测试也只有一个 cookie，没有测 Supabase 常见的多 chunk auth cookies。

这是 robustness P2，不阻塞 Stage3。
