# 但我发现一个新的 P1：数据库文档和 migration 已经漂移

这是这一轮最值得注意的问题。

你现在更新了 `docs/06_DATABASE_SCHEMA_AND_DATA_DICTIONARY.md`，增加：

```text
repetition_count
repetition_penalty
```

commit diff 里可以确认。

JSON `XpTransaction` 也已经有这两个字段。

但是上一轮新增的真实 Supabase migration：

```text
supabase/migrations/0009_xp_transactions.sql
```

**这一轮没有修改。**

而上一轮我读到的 migration 仍然只有：

```sql
activity_type text,
xp_type text,
amount integer,
base_amount integer,
modifier_json jsonb,
...
```

并没有：

```sql
repetition_count
repetition_penalty
```

所以现在出现了：

```text
TypeScript model
        ✅ repetitionCount
        ✅ repetitionPenalty

Data dictionary
        ✅ repetition_count
        ✅ repetition_penalty

Supabase migration
        ❌ repetition_count
        ❌ repetition_penalty
```

这就是典型 **schema drift**。

### 为什么现在不算 blocker？

因为 Supabase migration 目前还没有真正执行，项目仍在 JSON Demo 阶段。

### 为什么必须在接 Supabase 前修？

否则一旦下一阶段直接执行 migration，数据库结构会落后于当前 domain model。

因此我把它定义为：

# **P1 — 接 Supabase 前必须修**

最简单：

```sql
repetition_count integer not null default 0,
repetition_penalty numeric not null default 1,
```

具体 numeric 精度可以再定。
